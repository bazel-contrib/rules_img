# Vendored `go-erofs`

This directory is a copy of [`github.com/erofs/go-erofs`](https://github.com/erofs/go-erofs)
with three unmerged commits and one local bug fix applied on top. It is vendored
rather than declared as a module dependency because those commits are not upstream
yet, so there is no released version to depend on.

## Provenance

The vendored tree is `direntry/go-erofs` at branch `mkdir-synthesized`, which is
upstream `main` at:

    44d5e74d4dfbc6c23985fa805cec66cc57fb8558  Fix FileInfo.Mode() dropping setuid/setgid/sticky on the read path

plus the following three commits, in order:

| Commit | Subject |
|---|---|
| `ee54aa427fe4a4fed270eae9f48b0ecffe27c8a2` | Add a streaming writer with an up-front layout plan |
| `8a184904bb4edbe149b99898e12cb3f2a95e03c7` | Add AddFile and exported file-type mode constants |
| `39fcfa1a4185e5289ea7c0638aa5586d41908e48` | Add MkdirSynthesized |

`patches/0001`–`0003` hold those three commits as `git format-patch` output, so
they can be replayed onto upstream or rebased when upstream moves. They apply to
`44d5e74d4dfbc6c23985fa805cec66cc57fb8558`, not to the current upstream `main`,
which has advanced past it.

On top of the three commits, this copy carries one bug fix of its own,
`patches/0004-fix-device-table-offset.diff`. Unlike the others it is a plain
`git diff` rather than a `git format-patch` mailbox, so apply it with `git apply`
after the first three, not with `git am`:

- **The superblock's `devt_slotoff` pointed at the superblock instead of the
  device table.** The field counts device-slot-sized units — the kernel and
  erofs-utils both resolve it as `devt_slotoff * EROFS_DEVT_SLOT_SIZE` — and the
  table follows the superblock, so the only correct value is `(1024 + 128) / 128`;
  the writer used `sizeof(superblock) / 16`, which is the unrelated `sb_extslots`
  scale. It fails silently: a chunk index naming an explicit `device_id` never
  consults the slot, and the slot misread from the superblock's zeroed
  `volume_name` yields `blocks = 0` and no unified mapping, so a reader falls back
  to the metadata image rather than reporting an error. The patch includes a
  regression test.

Nothing in rules_img is affected — `erofscas` writes single-device,
self-contained images and never emits a device table — so this matters only to
the multi-device and rebuild paths.

The three commits add what an image builder needs in order to plan a layer before
writing it: `Prepare()` returns the byte layout of the image up front, `WriteTo`
serializes it metadata-first, and `Link`/`ShareData`/`SetToken`/`MkdirSynthesized`
plus the `WithUUID`/`WithInlineThreshold`/`WithSyntheticDirMetadata` options
expose the rest of what `img_tool/pkg/erofscas` drives. All of it is additive;
nothing upstream changed behaviour.

## Local modifications

Beyond the three commits and the bug fix above, this copy differs from the fork
in ways that are mechanical and confined to making it build inside this
repository:

- `go.mod` is deleted. The code is part of the `img_tool` module.
- Import paths are rewritten from `github.com/erofs/go-erofs` to
  `github.com/bazel-contrib/rules_img/img_tool/pkg/go-erofs`. The package name is
  still `erofs`, so importers alias it.
- `README.md` is replaced by this file.
- `cmd/erofs-cli`, `.github/` and `.golangci.yml` are dropped: a standalone CLI
  binary and upstream's own CI and lint configuration have no role here.
- `BUILD.bazel` files are generated by gazelle, as everywhere else in this
  module.

The Go sources are otherwise byte-identical to the fork apart from the import
path rewrite and `patches/0004`, and the tests came along with them.

## Updating

1. Rebase the patches onto the upstream commit you want, and get them merged
   upstream if possible -- then this directory can be deleted in favour of a
   module dependency.
2. Otherwise: re-run the copy, delete `go.mod`, rewrite the import paths, refresh
   `patches/0001`-`0003` with `git format-patch <base>..<branch>` and any
   remaining local fixes with `git diff`, and update the commit identifiers above.

Every patch here should be either upstreamed or dropped; the bug fixes especially,
since carrying them locally means an image this copy writes and one upstream writes
disagree.
